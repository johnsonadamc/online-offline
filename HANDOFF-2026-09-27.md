Only a ruler on paper can.
- Fixes: mirrored same-scale edge strips (any cut position now continuous); Option D symmetric bleed; `safetyInsetIn` stays 0.1; gutter shadow suppressed in print (0.9mm of it survived at the fold); SAFE_INSET 16px template rule; index labels moved inside the trim (four templates — Spread2, Spread4, Spread6, SpreadMosaic — had them −3…+1px from the trim, i.e. in or on the bleed).
- **Viewer artefacts that are NOT defects**: the two-page PDF view shows each page's spine bleed + mirror strip side by side, so anything crossing the fold looks doubled/kinked (~43px of duplicated content). On paper the cut removes the mirror strip entirely and the spread continues across the fold. The fold-preview recipe (crop both pages at 25px and butt them with PIL) shows the printed result.

## 4. Template sets (the mechanism for artist-designed issues)

- A set lives in `src/magazine/templates/sets/<name>/` with `manifest.ts` (`name`, `provides`, `files`, optional `fontCss`, `nameMap`, `adapt`). The loader concatenates the set into the **same** babel block as base, wrapped in an IIFE, between base template code and the bootstrap (a second script block does not work — the `window[_name]` bootstrap runs in the same block). Base resolves primitives as globals, so a set publishing e.g. `Folio` via `window` overwrites base's; the loader **snapshots base's 49 published names (count at f815a91) before the IIFE and afterwards restores every name not in `provides`, deleting any that did not exist before** (list derived from base's own `Object.assign(window, …)` calls at load time; throws if it finds none).
- Activation: `--set=<name>` on `test-generator.ts` > `periods.template_set_name` (migration in `scripts/migrations/`, applied to Supabase 26 Sep) > base. `null`, `''` and `'base'` all mean base, so `--set=base` forces base. No set ⇒ byte-identical to before. Selection, print profiles, page counts untouched by sets.
- A set may not change W/H/BLEED/SAFE_INSET, page size, single-vs-spread, selection, bleed geometry; must publish only page components; no `clampWords`-style truncation of contributor text.
- **Blue Hour** (`design/blue-hour/` pristine export; `sets/blue-hour/` ported): full Claude Design issue with its own THEME/primitives/fonts; it provides 17 page types (CampaignPage and MusicPage fall through to base). Adapter maps contract → kit shape (Cover→CoverA, Endpaper→BlankPage, participants from entries, curator_name from first message recipient, Colophon about_text constant, volume 'I'→1 rendered "Vol. 01"; cover_image absent ⇒ no frame). Renders Lena at 19 slots / 29 pages through the real pipeline with real fonts and images. **It is a loader test rig, never a shippable issue (AI-generated).** Not printed; decided not worth $15 until copy two answers the fold question.
- The **artist port target** is exactly Blue Hour's file shape: THEME object + components `function Name({ data, theme = THEME })` + `Object.assign(window, …)`. Artist supplies Figma frames + style sheet; Claude Code ports into that shape; the contract doc + kit rules block are the brief.
